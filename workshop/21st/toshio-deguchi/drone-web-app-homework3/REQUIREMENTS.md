# REQUIREMENTS

## 概要

ドローンを Web ブラウザから操作できる最小構成のアプリケーション。FastAPI + WebSocket によるバックエンドと、素の HTML/JavaScript/CSS によるフロントエンドで構成し、pymavlink 経由で MAVLink 機体（SITL 含む）と通信する。

## 目的

既存の CLI ベースのドローン制御体験を、Web ブラウザから直感的に操作できる形に置き換える。ユーザーはブラウザ上で機体へ接続し、状態をリアルタイムに確認しながら基本的な飛行操作を実行できるようにする。

## ターゲットユーザー

- ドローン開発者・研究者で、SITL や実機に対して簡易な操作 UI から動作確認を行いたい人
- CLI ツールに不慣れで、ブラウザから直感的にドローンを操作したい人

## 機能要件

- ブラウザからのボタン操作による MAVLink 接続開始（自動接続はしない）
- WebSocket を用いたコマンド送信（アーム、ディスアーム、離陸、着陸、GoTo、モード変更）
- 機体状態（接続状態、アーム状態、フライトモード、緯度、経度、高度、ヘディング、バッテリー残量）のリアルタイム表示
- バッテリー残量表示領域の背景色を残量に応じて変化させる（60%以下: 黄色 / 40%以下: ピンク色 / 30%以下: 赤色 / 20%以下: 赤色点滅。より深刻な条件を優先）
- Leaflet 地図上での機体位置マーカー表示、位置更新に伴う地図追従（緯度・経度が初期値 `(0, 0)` の間は描画しない）
- 飛行軌跡のポリライン表示、WebSocket 再接続時のクリア
- スマートフォン幅でも崩れないレスポンシブ UI

## 非機能要件

- ビルドツール不要のフロントエンド構成（素の HTML/JS/CSS）
- WebSocket 処理・MAVLink 受信処理がイベントループをブロックしないこと（executor 経由での実行）
- 未接続時にコマンドを送信してもサーバーが落ちないこと
- コマンド送信と状態更新を疎結合にし、コマンドの成否を即断せずテレメトリー受信ベースで状態を反映すること
- MAVLink の HEARTBEAT 発生源を選別し、GCS 等のなりすまし・チラつきを防止すること
- 離陸コマンド送信後、機体が実際に浮上する前に GoTo コマンドが送信され、離陸自体がキャンセルされてしまわないこと（浮上を確認するまで GoTo の送信を待機する）

## 将来拡張案

- 複数機体（マルチビークル）対応
- 認証・アクセス制御の追加
- ミッション（Waypoint）計画・アップロード機能
- 飛行ログの保存・再生機能
- テレメトリーのグラフ表示（バッテリー電圧、対気速度など）
- バッテリー残量低下時のアラート通知（音・プッシュ通知等）
